# 仪表盘与生产数据治理设计

## 目标

本模块为 Web 管理端提供只读的数据总览和生产数据治理入口，解决三个问题：

1. 管理员能看到系统使用量、评测吞吐和质量，而不需要直接查询 MySQL。
2. 管理员能发现过期、闲置、未评测或异常卡住的数据，但部署本身不会自动删除业务数据。
3. 高风险操作已有审计记录可以分页、筛选和追溯。

当前完成的是服务端数据面和 API。前端仪表盘只需要消费聚合结果，不应自行拼接多个业务列表或下载普通用户的会话正文进行统计。

## 仪表盘

接口：

```text
GET /api/v1/admin/dashboard?days=30
```

`days` 允许 7 至 90，默认 30。时间窗口按 UTC 自然日生成，缺少数据的日期也返回零值，方便图表保持连续。

返回内容：

| 区域 | 指标 |
|---|---|
| 用户 | 总用户、启用、禁用、管理员数量 |
| 会话 | 总量、窗口内新增、ready/active/completed/error、翻译记录总数 |
| 存储 | 对象总数、音频数、文本数、逻辑字节数、磁盘剩余、配额和保留空间 |
| 数据集 | draft/ready/archived、条目总数 |
| 评测 | queued/running/各终态、完成与失败样本数、ASR/分段 CER/WER、分段 Precision/Recall/F1 |
| 趋势 | 每日会话数、评测任务数、完成样本数、失败样本数 |
| 最近任务 | 最近 10 个评测任务的状态、进度、配置快照和质量指标 |

质量汇总继续使用全语料的原始分子和分母，不平均逐条百分比。没有人工分段标注时 `segment_evaluable=false`。

### 隐私边界

仪表盘只查询 `COUNT`、`SUM` 和任务级指标，不查询或返回：

- 密码摘要和令牌摘要。
- 普通用户邮箱列表。
- 会话的 ASR 原文、译文、摘要。
- 上传文件内容或内部磁盘路径。

接口位于管理员路由组，同时要求有效 Access Token、完成首次改密和 `admin` 角色。普通用户访问返回 403。

## 治理报告

接口：

```text
GET /api/v1/admin/governance/report
```

报告按照环境配置计算以下候选：

- `stale_draft_datasets`：超过草稿保留期仍未发布的数据集。
- `unreferenced_objects`、`unreferenced_object_bytes`：尚未被任何数据集引用的上传对象。它们可能是待使用资料，不等于可以直接删除。
- `ready_datasets_without_successful_evaluation`：当前修订没有成功评测的 ready 数据集。
- `stuck_evaluation_jobs`：排队或运行时间超过阈值的任务。
- `expired_active_tokens`：已经过期但尚未标记撤销的令牌。
- `revoked_or_expired_tokens`：可以进入令牌表维护流程的数据。
- `sessions_past_retention`：超过会话保留期且已结束的会话。
- `evaluation_jobs_past_retention`：超过评测保留期的终态任务。
- `audit_events_past_retention`：超过审计保留期的事件。
- 磁盘剩余空间与强制预留空间。

报告是候选清单的计数，不执行自动删除。原因是“未引用对象”可能仍在标注流程中，旧评测可能承担基线用途，用户会话和审计记录还可能受到业务、合同或合规保留要求约束。生产环境必须先由负责人确认策略和备份，再使用现有显式删除/归档接口或受审计的运维脚本处理。

## 审计查询

接口：

```text
GET /api/v1/admin/audit-logs
```

支持 `offset`、`limit`，以及：

- `action`
- `result=success|denied`
- `actor_user_id`
- `resource_type`
- `date_from`、`date_to`，格式为 RFC3339

响应包含操作者、动作、资源、来源 IP、User-Agent、结果、结构化详情和时间。审计表保持只追加；业务接口没有修改或删除单条审计事件的能力。

## 数据生命周期

```text
上传对象 -> 数据集草稿 -> ready 冻结 -> 评测任务 -> 质量指标 -> archived
    |            |             |            |              |
 SHA-256      revision      不可修改      配置快照       审计记录
```

- 上传对象以 UUID 和 SHA-256 标识，文件与 MySQL 元数据分离。
- 数据集草稿可编辑；ready 后冻结，评测记录 `dataset_id + revision`。
- 任务保存非密钥配置快照、逐条结果和全语料指标。
- 数据集归档不会删除对象或历史评测，保证基线可追溯。
- 测试和生产环境使用独立数据库、对象目录、Linux 用户、配置和密钥，不自动交换数据。

需要把测试数据引入生产时，应经过人工导出、校验 SHA-256、审批和生产导入；CI/CD 只部署代码，不迁移测试环境业务数据。生产发布仍由单独的人工工作流触发。

## 保留期配置

```yaml
governance:
  session_retention_days: 180
  evaluation_retention_days: 365
  audit_retention_days: 365
  stale_draft_days: 30
  stuck_job_minutes: 30
```

环境变量：

```dotenv
GOVERNANCE_SESSION_RETENTION_DAYS=180
GOVERNANCE_EVALUATION_RETENTION_DAYS=365
GOVERNANCE_AUDIT_RETENTION_DAYS=365
GOVERNANCE_STALE_DRAFT_DAYS=30
GOVERNANCE_STUCK_JOB_MINUTES=30
```

天数范围为 1 至 3650；卡住任务阈值为 5 至 1440 分钟。无效值回落到安全默认值。

## 前端展示建议

管理端第一屏应是工作型仪表盘，而不是宣传页：

- 顶部使用紧凑指标条展示活跃用户、窗口内会话、存储占用和失败样本。
- 中部使用一张连续日趋势图和任务状态分布。
- 质量区并排显示 ASR CER/WER 与分段 CER/WER/F1，明确标注评测样本数。
- 风险区显示治理报告中非零项目，并链接到对象、数据集、任务或审计列表。
- 最近任务使用表格，状态、进度、数据集修订和失败数可直接扫描。

前端不应缓存审计日志或用户数据到持久化浏览器存储。当前浏览器认证仍需要完成 HttpOnly Refresh Cookie 与 CSRF 方案后再正式开放公网管理页面。

## 运维规则

1. 测试环境可随 `main` CI/CD 自动更新代码和执行幂等数据库迁移。
2. 生产环境只允许人工触发发布工作流。
3. 部署不会自动执行数据清理、跨环境复制或生产数据回填。
4. 清理前必须备份 MySQL 与对象目录，并保证属于同一备份批次。
5. 审计日志、业务数据库和对象目录的访问权限保持最小化，不向仪表盘暴露密钥或绝对路径。
