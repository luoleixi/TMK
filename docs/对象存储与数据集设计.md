# 对象存储与数据集设计

## 结论

当前实现使用“同机独立目录 + MySQL 元数据”，不把音频或文本二进制写进 MySQL：

- MySQL 保存对象 ID、文件名、大小、SHA-256、磁盘相对路径、数据集和配对关系。
- 文件保存在服务端本地磁盘，默认目录是工作目录下的 `./data/objects`。
- systemd 的工作目录分别为 `/var/lib/tmk/test` 和 `/var/lib/tmk/production`，因此实际目录分别是 `/var/lib/tmk/test/data/objects` 与 `/var/lib/tmk/production/data/objects`。
- 测试与生产的数据库、文件目录、Linux 用户和配置均隔离。

这满足当前没有独立对象存储服务器预算的情况。文件与 MySQL 可以位于同一台服务器甚至同一块数据盘，但必须使用不同目录，不能将大音频存为 MySQL `BLOB`。这样不会让数据库备份、复制、缓存和查询被大文件拖慢，后续迁移到 S3、OSS 或 MinIO 时也只需要替换对象存储实现。

## 存储结构

上传后的对象使用服务端生成的 UUID，不信任用户文件名作为路径：

```text
/var/lib/tmk/production/data/objects/
├── .tmp/                         # 上传中的临时文件
└── 2026/
    └── 08/
        ├── <uuid>.wav
        └── <uuid>.txt
```

写入流程为：临时文件流式写入 -> 同步到磁盘 -> 设置 `0640` 权限 -> 原子重命名。写入时同时计算 SHA-256，不需要再次读取整个音频。路径解析拒绝绝对路径、反斜杠和 `..` 越界，下载只能通过鉴权 API 按对象 ID 完成，磁盘路径不会出现在 JSON 响应中。

当前支持：

| 类型 | 扩展名 | 校验 |
|---|---|---|
| 音频 | `.wav`、`.mp3`、`.flac`、`.ogg`、`.m4a`、`.webm` | 文件扩展名与文件头签名必须一致 |
| 文本 | `.txt`、`.md`、`.json`、`.srt`、`.vtt` | 必须是有效 UTF-8 且不能包含 NUL 字节 |

默认限制为单个音频 500 MiB、单个文本 10 MiB、每个上传用户 5 GiB、全环境 20 GiB，并始终预留 2 GiB 可用磁盘。上传配额检查和写入在当前单实例内串行，防止两个并发上传同时越过配额。

## 数据库变更

Admin API 启动时在独立 MySQL 数据库中执行幂等建表。对象元数据和数据集管理属于控制面，不写入 Glance 的用户权限表。

### `storage_objects`

一行对应一个不可变文件，保存：

- `id`：公开对象 UUID。
- `owner_user_id`：上传管理员，外键关联 `users`。
- `kind`：`audio` 或 `text`。
- `original_name`、`content_type`、`size_bytes`、`sha256`：展示、下载和完整性信息。
- `storage_key`：对象存储内部相对路径，唯一且不通过 API 暴露。
- `status`：`ready` 或删除过程中的 `deleting`。
- `created_at`、`deleted_at`：生命周期时间。

建立 `(owner_user_id, created_at)` 和 `sha256` 索引。SHA-256 当前用于校验和审计，不自动去重，以免不同管理员上传同一内容时产生隐式所有权关系。

### `datasets`

保存数据集的名称、描述、语言、状态、修订号、条目计数、创建人及时间。`revision` 在修改元数据、增删条目和发布时递增，后续评测任务可以记录使用的 `dataset_id + revision`，确保结果可复现。

状态机：

```text
draft --发布--> ready --归档--> archived
  |
  +--可修改名称、语言、条目
  +--可删除
```

`ready` 和 `archived` 都不可修改或删除。发布要求至少有一个条目，避免产生空的可评测数据集。

### `dataset_items`

一个条目将一个音频对象与一个参考文本对象配成评测样本，保存顺序、备注、创建人和时间。可选的 `reference_segments_json` 保存人工分段标注；旧数据默认是空数组，只参与 CER/WER，不参与分段 Precision/Recall/F1。数据库约束保证：

- 数据集内顺序唯一。
- 同一个音频不能在同一个数据集中重复出现。
- 音频、文本、数据集和创建人都必须存在。
- 删除数据集草稿时条目级联删除；仍被任意条目引用的文件不能删除。

服务层还会检查对象状态和类型，不能把文本放进音频字段，也不能引用正在删除的对象。

## 一致性与删除

上传采用“先写文件、后写元数据”：数据库写入失败时立即删除已写文件。删除采用相反的两阶段流程：

1. 数据库将对象从 `ready` 标记为 `deleting`，同时确认没有数据集引用。
2. 删除磁盘文件。
3. 删除数据库元数据。

如果磁盘删除失败，状态会恢复为 `ready`；如果磁盘已删除但最后一步数据库失败，下次删除请求可从 `deleting` 状态继续，操作是可重入的。列表和下载只暴露 `ready` 对象，因此中间状态不会被新数据集引用。

## 权限与审计

所有对象与数据集接口位于 `/api/v1/admin`，必须满足：有效 Access Token、已完成首次改密、角色为 `admin`。上传、删除、创建/修改数据集、增删条目、发布和归档都会写入 `audit_logs`。

目前管理员共享管理整个评测资料库。`owner_user_id` 和 `created_by` 已保留归属信息；如果以后增加标注员角色，可以在不改文件结构的情况下加入按项目或组织的数据权限。

## API

对象接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/admin/objects?kind=audio|text` | `multipart/form-data` 上传，字段名为 `file` |
| `GET` | `/api/v1/admin/objects` | 分页列表，可用 `kind` 过滤 |
| `GET` | `/api/v1/admin/objects/usage` | 用户用量、总用量、配额和磁盘余量 |
| `GET` | `/api/v1/admin/objects/{id}` | 查询元数据 |
| `GET` | `/api/v1/admin/objects/{id}/content` | 鉴权下载 |
| `DELETE` | `/api/v1/admin/objects/{id}` | 删除未被数据集引用的对象 |

数据集接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/admin/datasets` | 创建草稿 |
| `GET` | `/api/v1/admin/datasets` | 分页列表，可按状态过滤 |
| `GET` | `/api/v1/admin/datasets/{id}` | 查询数据集及全部条目 |
| `PATCH` | `/api/v1/admin/datasets/{id}` | 修改草稿元数据 |
| `DELETE` | `/api/v1/admin/datasets/{id}` | 删除草稿 |
| `POST` | `/api/v1/admin/datasets/{id}/items` | 增加音频与参考文本配对 |
| `DELETE` | `/api/v1/admin/datasets/{id}/items/{item_id}` | 删除草稿条目 |
| `POST` | `/api/v1/admin/datasets/{id}/ready` | 发布并冻结数据集 |
| `POST` | `/api/v1/admin/datasets/{id}/archive` | 归档已发布数据集 |

列表接口统一支持 `offset` 和 `limit`，`limit` 最大为 100。

增加条目时可直接附带分段标注：

```json
{
  "audio_object_id": "<audio-uuid>",
  "reference_text_object_id": "<text-uuid>",
  "reference_segments": [
    {"text": "第一句话。", "begin_time_ms": 0, "end_time_ms": 1800},
    {"text": "第二句话。", "begin_time_ms": 1800, "end_time_ms": 3600}
  ]
}
```

最多允许 2000 段、合计 100 万个 Unicode 字符。文本不能为空；时间不能为负或倒序。时间字段为未来的边界容差和延迟指标预留，当前分段 F1 使用有序文本匹配。

## 部署配置

YAML 示例：

```yaml
object_storage:
  driver: local
  root: "./data/objects"
  max_audio_bytes: 524288000
  max_text_bytes: 10485760
  per_user_quota_bytes: 5368709120
  total_quota_bytes: 21474836480
  min_free_bytes: 2147483648
```

所有值都可以通过环境变量覆盖：

```dotenv
OBJECT_STORAGE_DRIVER=local
OBJECT_STORAGE_ROOT=./data/objects
OBJECT_STORAGE_MAX_AUDIO_BYTES=524288000
OBJECT_STORAGE_MAX_TEXT_BYTES=10485760
OBJECT_STORAGE_PER_USER_QUOTA_BYTES=5368709120
OBJECT_STORAGE_TOTAL_QUOTA_BYTES=21474836480
OBJECT_STORAGE_MIN_FREE_BYTES=2147483648
```

服务启动时会创建存储目录；目录无法创建或无权限时服务拒绝启动。现有 systemd 单元只允许写入 `/var/lib/tmk/<environment>`，默认路径正好位于该范围内，不需要扩大文件系统权限。

## 备份与恢复

MySQL 备份和对象目录必须作为同一份业务备份管理。最稳妥的步骤是短暂停止写入或停止对应环境服务，然后：

1. 导出该环境 MySQL 数据库。
2. 备份该环境的 `data/objects` 目录，并保留文件权限。
3. 将数据库备份和对象备份放进同一备份批次，记录时间和环境。
4. 恢复时先恢复 MySQL，再恢复到配置中的对象目录，最后启动服务并抽查 SHA-256。

至少保留异机备份；同一服务器或同一数据盘上的第二份副本不能应对整机或磁盘故障。磁盘接近 `min_free_bytes` 时上传会返回 HTTP 507，此时应扩容或归档，而不是降低到零。

## 后续迁移到 OSS/MinIO

业务表只保存 `storage_key`，不依赖本地绝对路径。当前测试环境使用同机文件目录，未来可切换到 S3/OSS/MinIO 兼容对象存储。切换前必须校验 SHA-256 和读写权限；数据集表和 API 合同不绑定具体存储实现。
