# 异步评测任务设计

## 这一环节处理什么

异步任务处理离线评测，不参与桌面客户端的实时同传。管理员选择一个已发布的数据集后，服务在后台逐条完成：

1. 固化数据集修订号、语言和本次 ASR/分段器配置。
2. 将音频统一为 ASR 所需的 16 kHz、16-bit、单声道 PCM 流。
3. 调用 ASR 生成原始识别文本。
4. 使用与实时同传相同的分段器生成分段文本及每段时间信息。
5. 分别将 ASR 原文、分段后文本与人工参考文本比较，计算 CER 和 WER。
6. 保存每条样本的输入、输出、分段、指标和错误，并持续汇总任务进度。

它适合处理耗时长、有外部 API 调用、可能局部失败且不应占住 HTTP 请求的工作。上传文件、编辑数据集、普通查询仍是同步接口；翻译不属于本轮评测范围。

## 当前架构选择

当前采用“应用内工作池 + MySQL 持久化队列 + 同机对象目录”：

```text
管理后台 --POST 202--> evaluation_jobs(MySQL)
                              |
                     后台 worker 抢占 queued 任务
                              |
         本地对象目录 -> 音频解码 -> ASR -> 分段器 -> CER/WER
                              |
                    evaluation_results(MySQL)
```

没有引入 Redis、RabbitMQ、独立 worker 服务或新的服务器。原因是当前文件存储是本机磁盘，多实例 worker 即使共享了数据库也无法读取其他机器上的文件。一个服务进程可运行 1 到 8 个 worker，并通过数据库条件更新抢占任务；生产默认 1 个，避免同时调用 ASR 造成费用和限流压力。

此方案适合目前的单机部署。将来迁移到 OSS、S3 或 MinIO 后，可以把同一个 worker 包拆成独立进程，再按需要引入专用消息队列；HTTP API 和结果表不需要推倒重做。

## 状态与可靠性

任务状态流转：

```text
queued -> running -> succeeded
                  -> completed_with_errors
                  -> failed
                  -> queued（基础设施错误，指数退避重试）
                  -> dead_lettered（超过最大尝试次数）
queued/running -> cancelled
```

- `succeeded`：所有样本均成功。
- `completed_with_errors`：批次执行完成，但部分样本失败；成功样本及指标仍可使用。
- `failed`：数据集快照异常或结果无法持久化等批次级错误。
- `dead_lettered`：基础设施错误或 Worker 租约连续失败并达到最大尝试次数，等待管理员人工重试。
- `cancelled`：管理员取消；正在进行的音频解码与 ASR 会收到取消信号。

Worker 领取任务时写入唯一 `lease_owner`、`lease_expires_at` 和 `heartbeat_at`，并递增 `attempt_count`。执行期间持续续租；所有结果保存和任务完成操作都必须同时匹配任务状态、租约所有者和租约有效期。因此旧进程即使在网络恢复后继续执行，也不能覆盖新 Worker 的结果。

服务只回收已经过期的租约，不会再在启动时无条件重置所有 running 任务。基础设施错误按 5、10、20 秒等指数退避，最长 15 分钟；达到 `max_attempts` 后进入死信。管理员可以从后台将死信任务重新入队，并追加一组尝试次数。

逐条结果通过 `(job_id, dataset_item_id)` 保证幂等。重试保留已经成功写入的结果和聚合指标，只处理尚未完成的条目；重复保存同一条结果不会再次增加 completed、CER/WER 或分段统计。单条样本有独立超时，业务评测失败作为逐条结果保存，不会错误地触发整个任务的基础设施重试。

服务正常关闭时停止领取新任务，取消正在执行的 ASR/解码，并立即释放自己持有的租约；这类关闭不消耗重试次数。管理员取消会写入 cancelled 并清除租约，之后旧 Worker 的写入会被租约围栏拒绝。

数据集发布后不可修改。任务同时记录 `dataset_id`、`dataset_revision`、语言和非密钥配置快照，避免排队期间配置变化导致同一任务内部口径不一致。API 密钥不会写入任务表；云端模型自身升级属于外部可复现性边界。

## 数据库变更

服务启动时通过现有迁移入口为 MySQL 和 SQLite 幂等创建两张表。

### `evaluation_jobs`

每行代表一个批次，主要保存：

- 数据集 ID、修订号、语言和 JSON 配置快照。
- `total_items`、`completed_items`、`succeeded_items`、`failed_items`。
- ASR 原文和分段文本各自的字符/词编辑距离与参考单位数。
- 匹配分段数、预测分段数和人工参考分段数。
- 请求管理员、状态、批次错误及创建/开始/完成时间。
- 尝试次数、最大尝试次数、下一次重试时间、租约所有者、租约过期时间和最后心跳时间。

聚合值保存“编辑距离总和 / 参考单位总和”，而不是把每条百分比取平均，避免短音频和长音频权重相同。建立 `(status, created_at)` 队列索引和 `(dataset_id, created_at)` 查询索引。

### `evaluation_results`

每行对应任务中的一个数据集条目，保存参考文本、ASR 文本、分段文本、分段 JSON、四组文本指标原始计数、三组分段匹配计数、状态、错误和执行时间。`(job_id, dataset_item_id)` 唯一，避免恢复或并发处理产生重复结果；按 `(job_id, sequence)` 建索引供详情分页展示。

结果删除策略当前跟随任务：表外键支持删除任务时级联删除结果，但本轮没有开放删除任务 API，以保留评测审计记录。数据集和条目被结果引用时不能删除；已发布数据集本身也不可删除。

## 指标口径

CER 使用 Unicode 字符：转小写，并忽略空白、标点和符号后计算 Levenshtein 编辑距离。WER 将标点视为词边界，转小写并按空白分词后计算。两者公式均为 `(替换数 + 删除数 + 插入数) / 参考单位数`；实现保存编辑距离和参考单位数，因此批次指标是全语料加权结果，不是逐条百分比的简单平均。接口同时返回原始计数，以及计算后的：

- `asr_cer`、`asr_wer`：参考文本对比原始 ASR 文本。
- `segmented_cer`、`segmented_wer`：参考文本对比分段拼接文本。

这样可以区分“识别模型本身的误差”和“分段过程是否丢字、重复或改变文本”。

### 分段评测

数据集条目可以提供有序的 `reference_segments` 人工标注。服务先验证这些分段拼接后与参考全文在 CER 归一化口径下完全一致；不一致的条目直接失败，避免用错误标注生成指标。

预测分段与参考分段都执行与 CER 相同的大小写、空白和标点归一化，然后使用最长公共子序列做一对一有序匹配。这样重复段不能被多次计数，改变顺序也不会获得匹配。指标为：

- `segment_precision = matched / predicted`：预测出来的段中有多少与人工分段完全一致。
- `segment_recall = matched / reference`：人工参考段中有多少被完整恢复。
- `segment_f1`：Precision 和 Recall 的调和平均。
- `segment_count_delta = predicted - reference`：正数倾向过度分段，负数倾向合并过多。

任务级指标累计 `segment_matched`、`segment_predicted`、`segment_reference` 后统一计算，不对逐条 F1 做平均。没有 `reference_segments` 的旧数据仍可评测 CER/WER，接口返回 `segment_evaluable=false`，并且不会把其预测段数混入分段指标分母。

当前 F1 是“规范化文本完全一致的有序分段 F1”，会同时受到 ASR 错字影响；因此需要结合 `asr_cer` 判断失败来自识别还是分段。标注结构预留 `begin_time_ms`、`end_time_ms`，但现有分段器输出尚无可靠的段级时间边界，所以本轮不伪造时间容差命中率或提交延迟指标。

逐条结果中的 `segments` 同时保留每段的 `text`、`reason`、`revision` 和 `is_final`。`reason` 可以区分标点、最大长度、最大时长、ASR 最终句、软提交和任务结束刷新，便于在管理后台定位过度分段来自哪条策略。

中文、日文等没有天然空格边界的语言以 CER 为主指标。当前 WER 只按显式空格和标点分词：它适用于英语等空格分词语言，但不能替代中文分词器。为了保证历史任务口径稳定，本轮不在指标内部隐式引入会变化的词典分词；将来如需中文 WER，应把分词器名称和版本一并写入任务配置快照。

当参考文本为空且识别结果也为空时错误率为 0；参考为空但识别产生内容时返回 1，表示该条完全错误。一般情况下插入很多内容会使 CER/WER 大于 1，接口不会把它截断到 100%。

## API

所有接口均位于 `/api/v1/admin`，要求管理员 Access Token 且已完成首次改密。

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/evaluation-jobs` | 为 ready 数据集创建任务，返回 `202` |
| `GET` | `/evaluation-jobs` | 分页查询，可按 `status` 过滤 |
| `GET` | `/evaluation-jobs/{id}` | 查询配置快照、计数、`progress` 和汇总指标 |
| `GET` | `/evaluation-jobs/{id}/results` | 按数据集顺序分页查询逐条结果 |
| `POST` | `/evaluation-jobs/{id}/cancel` | 取消 queued 或 running 任务 |
| `POST` | `/evaluation-jobs/{id}/retry` | 将 failed 或 dead_lettered 任务人工重新入队 |

创建请求示例：

```json
{
  "dataset_id": "<dataset-uuid>",
  "segmenter_enabled": true,
  "max_runes": 40,
  "max_duration_ms": 5000,
  "soft_commit_delay_ms": 300
}
```

分段器参数不传时使用服务当前配置。任务入队成功并不代表评测已完成，后台应轮询任务详情；`progress = completed_items / total_items`，其中 `completed_items = succeeded_items + failed_items`，终态后再拉取结果。任务和逐条结果都会返回 `segment_evaluable`、`segment_precision`、`segment_recall`、`segment_f1` 和 `segment_count_delta`。

## 音频与部署

标准 16 kHz、16-bit、单声道 PCM WAV 使用内置流式解析器，不需要额外程序。其他 WAV 规格及 `.mp3`、`.flac`、`.ogg`、`.m4a`、`.webm` 通过 `ffmpeg` 转为 PCM；宿主机未安装时对应样本会失败并记录明确错误，不影响其他样本。

生产机建议安装：

```bash
sudo apt-get install ffmpeg
```

`bootstrap-server.sh` 会检查并提示缺失，但不会阻止只使用标准 WAV 的部署。音频按 100 ms 块喂给实时 ASR，避免离线文件瞬间灌入；测试环境使用 mock ASR 时不等待。

配置示例：

```yaml
evaluation:
  workers: 1
  poll_interval_ms: 500
  item_timeout_seconds: 600
  chunk_interval_ms: 100
  lease_seconds: 60
  heartbeat_seconds: 15
  max_attempts: 3
  retry_base_seconds: 5
  reaper_interval_seconds: 10
```

对应配置均可使用同名大写环境变量覆盖，例如 `EVALUATION_LEASE_SECONDS`、`EVALUATION_HEARTBEAT_SECONDS` 和 `EVALUATION_MAX_ATTEMPTS`。测试与生产配置各自独立，队列、结果、对象目录和密钥也随各自数据库及运行目录隔离。

## 运维边界

- 当前只部署一个服务实例；本地对象目录不支持跨机器 worker。
- 增加 worker 会增加 ASR 并发和费用，调整前先确认云端配额。
- 数据库与对象目录必须进入同一个备份批次，做法见对象存储设计文档。
- 任务结果中的文本可能较大，详情接口默认每页 20 条，管理后台应使用分页。
- 进程在 ASR 调用完成但结果落库前崩溃时，该条音频可能再次调用云端 ASR；数据库幂等可以避免重复结果，但不能消除这段极小窗口内的外部调用费用。
