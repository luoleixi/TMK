# TMK 环境与发布规范

## 环境模型

- 服务端维护相互隔离的测试环境和生产环境，包括配置、数据库、密钥、日志和监控数据。
- 客户端只有一个正式发行渠道，不发布独立的测试版本。
- 开发和 CI 联调期间，客户端连接测试服务端；正式客户端固定连接生产服务端。

## 发布顺序

1. 服务端代码通过自动化测试后部署到测试环境。
2. 客户端使用测试环境配置完成接口和 WebSocket 联调。
3. 服务端部署到生产环境，并完成健康检查和冒烟测试。
4. 服务端生产验证成功后，才允许构建正式客户端。
5. 正式客户端经过人工审批后签名并发布。

任何步骤失败，都必须阻止后续客户端发布任务。

## 正式客户端构建

正式客户端只能通过 `scripts/build-client-production.ps1` 构建。该脚本需要：

- 自动设置 `TMK_ENV=production`。
- 使用 Go 的 `production` 构建标签。
- 清除或拒绝 `TMK_BACKEND_URL` 等后端地址覆盖变量。
- 校验最终使用的是生产服务端地址，发现测试地址、localhost 或回环地址时立即失败。
- 调用 Wails 正式构建任务并返回正确的退出码。
- 输出可追踪的版本号、Git commit 和构建时间。

CI/CD 发布流水线必须调用该脚本，不能直接执行普通 Wails 构建命令。脚本已实现并通过正式构建验证。

## 客户端产物目录

客户端构建产物必须按环境和版本号分目录保存：

```text
TMK-Client/bin/test/<版本>/TMK-Client-Test-<版本>.exe
TMK-Client/bin/test/<版本>/build-metadata.json

TMK-Client/bin/release/<版本>/TMK-Client-<版本>.exe
TMK-Client/bin/release/<版本>/build-metadata.json
```

- 测试客户端通过 `scripts/build-client-test.ps1` 构建，只连接测试服务端。
- 正式客户端通过 `scripts/build-client-production.ps1` 构建，只连接生产服务端。
- `TMK-Client/bin/` 根目录下的 exe 是 Wails 临时构建输出，不得作为发行版本分发。
- GitHub Actions 使用对应版本目录作为 Artifact；发行包不得提交到 Git 仓库。
- 旧的扁平目录产物属于历史文件，后续构建不得继续覆盖或发布。

本地构建测试客户端：

```powershell
./scripts/build-client-test.ps1 -Version test-local
```

## 兼容与回滚

- 服务端先于客户端发布，因此新服务端必须兼容仍在运行的旧客户端。
- 新接口或行为变化应使用 API 版本管理或特性开关控制。
- 客户端发布失败时，不应依赖回滚服务端恢复功能。
- 服务端生产部署失败或健康检查失败时，不得触发客户端构建与发布。

## CI/CD 命令

合并并推送 `main` 后，`.github/workflows/ci-cd.yml` 会执行后端竞态测试、客户端双构建标签测试、前端构建，并自动部署测试环境：

```powershell
git push origin main
```

生产环境只能通过手动流水线发布。服务端生产健康检查通过后，流水线才会调用正式客户端脚本并创建 GitHub Release：

```powershell
gh workflow run release-production.yml `
  -f version=v1.0.0 `
  -f confirmation=DEPLOY_PRODUCTION
```

## GitHub Secrets

GitHub 仓库需要创建 `test` 和 `production` 两个 Environment，并分别添加：

- `test`: `TEST_SSH_PRIVATE_KEY`
- `production`: `PROD_SSH_PRIVATE_KEY`

生产 Environment 必须配置 Required reviewers。部署私钥只允许保存在 GitHub Secrets，不得提交到仓库。

录入 GitHub Secrets 并验证流水线后，应删除本机私钥副本；公钥已经安装在服务器对应的受限部署账号中。

## 服务器运维

```bash
systemctl status tmk-glance@test
journalctl -u tmk-glance@test -f
curl https://117.72.159.185/tmk-test/api/health
```

生产环境发布前应确认：

```bash
systemctl is-active tmk-glance@production
test ! -e /opt/tmk/production/current
test ! -s /etc/tmk/production/tmk.env
```

部署流水线使用 gzip 压缩二进制后传输，服务器校验压缩包 SHA256 后再解压。部署脚本采用版本目录和原子软链接切换，新版本健康检查失败时会自动恢复上一个 `current` 目标并重启旧版本。
