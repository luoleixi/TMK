# TMK 精进方案

| 优先级 | 方向 | 为什么重要 | 是否完成 |
|---|---|---|---|
| P0 | 长句延迟治理 | 同传长句会产生大量 ASR 中间结果，如果逐条同步翻译会造成过期任务排队，直接破坏实时体验。 | 已完成 |
| P0 | SessionActor 架构 | 每个会话需要独立管理状态、音频流、ASR、翻译、取消和资源释放，避免不同会话互相影响。 | 已完成 |
| P0 | WebSocket 高并发 | 同传系统的核心压力来自大量长连接和持续音频帧，必须通过读写分离、有界队列和背压策略保证稳定。 | 已完成 |
| P1 | 限流、熔断、降级 | ASR 和翻译依赖外部服务，高并发或服务抖动时需要保护系统不雪崩。 | 未完成 |
| P1 | 全链路监控 | 需要观测音频接入、ASR、翻译调度、字幕推送和落库全过程，才能定位延迟和故障。 | 未完成 |
| P1 | 压测工具 | 需要用并发 WebSocket 音频流压测证明系统容量、延迟和资源释放能力。 | 未完成 |
| P2 | Docker 与云原生 | 容器化、Kubernetes、Redis 会话注册和 HPA 能体现服务可部署、可扩展和可运维能力。 | 未完成 |
| P2 | CI/CD 与测试体系 | 自动测试、构建和发布能把项目从功能 demo 提升为可持续迭代的工程项目。 | 已完成 |
